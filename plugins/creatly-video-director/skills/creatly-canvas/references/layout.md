# 节点布局：二维紧凑、整体接近正方形

新建一批节点、分组或用户要求整理布局时，默认充分利用横向和纵向空间，让本次内容及所在画布的实际占用范围尽可能长宽接近，而不是固定一个坐标、沿另一方向无限延伸。用户指定的顺序、版式、固定位置或长时间线优先；近正方形是排版目标，不要求任何内容强行做成正方形。

## 衡量实际空间

以画布显示尺寸计算包围框：宽 W = 最右边界 − 最左边界，高 H = 最下边界 − 最上边界，比较 W/H 与 1 的接近程度。不要只用节点数量决定“几乘几”；横版图片、竖版图片、视频、文本和分组可能尺寸不同，图片文件的 2K/4K 原始像素也不能直接当作节点显示尺寸。

只读取目标、父容器和必要周边的坐标、尺寸及容器关系，字段遵从实时 Schema；布局不需要拉全画布的正文、提示词和生成参数。未知尺寸按当前节点类型的实际默认显示尺寸估算，写入后回读校正，不把所有类型当成等大的方块。

## 排列方法

1. **先组内，再外层。** 保留既有分组和关联关系，先排子节点，再按内容边界与标题留白确定组尺寸。外层把完整分组当作一个矩形排布，不把组内节点又当根节点排一次。没有必要时不为凑形状新建分组。这里是布局计算顺序；实际新建时先取得真实父容器 ID，再保存子节点。
2. **分行、分列，达到合适宽度就换行。** 按用户顺序或原有逻辑，从左到右、从上到下阅读，采用尺寸自适应的网格或分行布局，不默认单列，也不默认一条无限长的横排。局部短依赖链保持可读方向，长链可跨行，不能为了排版改连线。
3. **根据尺寸选列数。** 同类节点可用 `列数 ≈ sqrt(节点数 × 平均高度 / 平均宽度)` 作为起点，取 1 到节点数之间的整数，再比较附近列数。每个候选按实际行内宽度、每行最大高度和间距算 W/H，选择更接近 1 且少空洞、不重叠的方案；不能机械把所有内容套成 3×3 或 4×4。
4. **间距和标题可读。** 节点边缘对齐，使用一致且适中的间距，给标题、端口和组标题留空；不同尺寸按本行最大高度推进下一行。避免标题盖住图片、节点互相重叠、分组套住内容后仍留下大片空白。
5. **新增时考虑已有整体。** 优先利用已知可用空位，并在不遮挡已有内容的情况下扩展整体较短的一边：当前画布很高时优先向左右补充，当前很宽时优先向上下补充。不能每次把新批次追加到最底部，形成“每批近方形、全画布仍是长竖条”。只移动本次新节点或用户授权整理的节点，保留其他手动布局。

例如，同为 12 个节点，显示尺寸约 320×180 的横版节点可先比较 3 列×4 行及相邻列数；180×320 的竖版节点可先比较 4 列×3 行及相邻列数。具体结果仍要算上间距、标题与实际尺寸，不把例子当固定模板。

## 写入、坐标与核对

- 新建时就按二维方案提供 position，不先把一批节点全堆在同一坐标或长单列里，再声称已经完成布局。
- 子节点 position 相对于 parentNode，组本身也相对于其父容器；计算整体边界时逐层累加得到画布坐标。写回时换回正确父容器的相对坐标，不把绝对坐标误写进组内，也不无意改变 parentNode。
- 整理通常只改 position 和必要的分组 dimensions。保留节点 ID、名称、正文、媒体、生成配置、主体关联、parentIds 和参考素材，不删节点、不复制产物、不重生成。保留图片/视频宽高比，不拉伸内容或缩成不可读的小块来凑方形。
- 使用当前工具实际支持的布局/节点写入字段，保留版本校验与幂等要求；不编造自动排版 MCP 工具或向未开放的字段传参。
- 写入后按 ID 回读布局，检查节点未重叠、内容在组内、标题可读、整体宽高更均衡。右侧画布可用时再查看实际排版；没有实际看图时区分坐标核对与视觉验收。
- 少量节点、固定版式或一段明确的线性流程可能不适合严格 1:1；保留可读性与用户要求，不用多余空白、无关节点或无休止重排换取数字上“正方形”。
