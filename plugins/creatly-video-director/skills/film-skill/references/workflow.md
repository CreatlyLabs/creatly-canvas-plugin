# 制作流程与授权

## 从实际依赖恢复

完整制作路线：剧本与规格 → 素材分析/视觉基准 → 元素与分镜设计 → 资产准备与分镜图 → 运镜/表演/生成单元 → 视频与音频 → 剪辑与导出。

这是依赖图，不是每次都重跑的表单。人物选角可在剧本认可后与文字分镜并行；已有认可素材直接复用。剧本修订时只标记真正受影响的镜头与资产。只学习构图、改提示词或整理已有视频时，不要求先另写新故事。

| 当前成果 | 下游推进前需要什么 |
|---|---|
| 新故事 | 人物目标、冲突、关键因果、对白和结局版本有认可依据，或用户授权自主选择 |
| 人物/场景/道具 | 当前故事与风格范围明确；按本次图片授权执行；选角结果与身份引用区分 |
| 文字分镜 | 观看任务、构图、状态衔接、对白容量成立；不必等所有资产完成才设计 |
| 视频生成单元 | 对应分镜/运镜、真实引用、前置音频、模型能力及本批费用均就绪 |
| 剩余音频 | 故事板与对白确定；不被生成引用的配乐/VO可与视频并行 |
| 剪辑 | 使用的媒体真实可访问；每个片段有验收、实际入出点与音轨映射 |
| 导出 | 交付格式明确，预览通过或用户授权代理验收后导出 |

原始参考文件只读。完整项目维护 Final_Video_Spec.md、Production_State.md、Storyboard.md；复杂剧本可另存 Script.md 并记录版本。局部工作只更新现有记录，缺工具时交付可执行方案和缺口，不伪造任务、资产或平台 ID。

## 确认分成两件事

**创作认可**决定采用哪个故事、演员、画面和剪辑；**费用授权**决定是否可以提交这批付费生成。一次用户回复可以同时覆盖两者，记录原意即可，不拆成重复问答。

- 默认新故事先给剧本，再在视觉方案/资产、视频预览等有实质变化的节点展示成果。
- 用户已认可剧本与人物、批准指定模型/数量/预算并说继续时，补齐可自行处理的设计和技术检查后继续，无需重问同一授权。
- 用户指定逐镜确认时按镜头保存待确认/需修正/已确认；连续推进授权则允许代理在范围内选择与验收，不能把代理决定标成用户亲自确认。
- 一批可包含多个节点。对话内确认本批范围、模型、数量与费用上限后，不新增画布确认步骤。调用参数支持预算上限时按实际 schema 传入；没有该参数也不能发明字段。
- 否定旧故事或候选后保留原件，更新版本与依赖；旧故事的生成授权不自动迁移到新故事。超数量、换模型、超上限或额外付费重试时才补充授权。
- 返回超时或结果不明时先查原任务，避免重复扣费；没有证据不宣布已生成或失败。

## 项目状态和恢复点

分别记录设计、用户认可、代理视觉验收、费用授权、提交、生成、挂载和导出状态。保存实际提交文本、参数、引用顺序、任务 ID、输出路径；修订提示词另存版本，不改写旧输出真实输入。

恢复工作时先读最近成果和授权，再查相关任务或媒体，不因文档写着“完成”就跳过缺失输入。服务或挂载问题与画面质量问题分开处理；平台故障不触发重新抽图。
