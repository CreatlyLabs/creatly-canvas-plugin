# 修订与恢复

先阅读 [MCP 执行协议](mcp-execution.md)，取得当前画布 JSON、原任务 ID 与真实媒体结果，再决定更新范围。

- 已有节点更新，缺失节点新建；保留已完成且仍有效的产物。
- 明确版本冲突时重新读取并评估人工修改，不把最新版本号强塞回旧请求。
- 网络超时不是操作失败；先查原任务与画布，不用新请求 ID 自动重试付费或写入。
- 新的生成尝试需要对应范围的授权与后端确认，不能复用不相关的历史批准。
- 上游变化影响下游引用和验收；先标明影响范围，再按用户要求推进。
- 仅查看生成状态，不会自动继续提交其他任务。

## 生成结果不理想时

不默认靠加禁止词、加形容词或把提示词写长来修。先判断问题出在哪一层，按下面顺序排查，做成本最低的修改：

剧本与人物逻辑 → 空间连续性（左右翻转、门窗漂移、瞬移、视线错）→ 站位与动作起止状态（动作跳状态、道具换手、坐站回滚）→ 镜头设计（一镜动作过多、摄影机同时推摇移）→ 提示词表达（前后冲突、重复过多）→ 重新生成 → 剪辑补救。

- 动作过载：保留一个主动作，次要动作与对白同步；仍不稳就拆镜头或拆段。
- 摄影机过载：一个镜头只保留一个主要运动意图，没有叙事动机时固定机位。
- 表演失真：把抽象情绪词改成呼吸、停顿、视线、手部和重心的变化过程，并给在场的倾听者具体反应。
- 同一镜头改了多轮仍不稳定：不要无限微调同一种写法，重新判断它是否超出当前模型能力，改镜头设计或剪辑方案。
- 只有确定问题主要来自模型随机性时，才直接重生成。
