# 主体创建

## 目标

只为需要跨镜头保持视觉或声音一致性的角色和场景创建主体。主体结构与主体参考图生成分成两个阶段；创建结构不等于生成完成。

## 先读取已有主体

按实时 Schema 用 subjectId/subjectQuery 定位后读取 `getCanvasContext(detail="full")` 的 subjects；首次建档需扫描现有主体时才取目录范围，复用同一版本的回执。用 getNodes 精读已有应用节点，具体字段见 [读取策略](mcp-execution.md#按需读取节点)。只以当前接口暴露的参数为准。

区分主体库 elementId、画布 subjectNodeId、主体素材 assetId 与媒体 fileRef.id；用名称、分类、素材内容和关联 ID 一起判断复用。普通 element 容器、同名节点或空的 subjects.subject 都不能证明正式主体已存在。名称大小写、空格和标点按服务端返回处理。

不要创建同名重复主体。若同名主体有多个且无法判断当前有效项，停止并请用户选择。

## 识别角色主体

先做角色名册扫描，再写角色参考图提示词。对每个候选角色记录：正式名称、全部称谓与别名、出现的 Scene 与 Shot、叙事功能、关键动作、外观证据和是否需要跨镜复用。

归并时遵守以下规则：

- 同一人的姓名、称谓、绰号和阶段性称呼合并为一个角色，不因称呼变化重复创建主体；
- 功能相同且不需要独立辨识的角色可以合并，但必须同步修改剧本和全部引用；
- 无名背景人物不进入主体名册；需要单独表演或反复出现的无名人物使用稳定的描述性名称；
- 原文没有提供的外观信息标记为导演提案，不伪装成素材事实；
- 先确定名册与复用范围，再为入选角色形成详细身份锚点，避免为一次性人物制作昂贵资产。

满足任一条件时通常创建角色主体：

- 剧本中的具名主要角色；
- 在两个或更多 Shot 中出现；
- 承载对白或关键动作；
- 外观连续性会影响故事理解。

以下内容通常不建主体：

- 单镜头群演或路人；
- 只作为模糊背影且不再出现的人；
- 抽象意象或无法形成固定外观的角色。

一次性人物直接在 Frame 提示词中描述，不要创建无复用价值的主体。

## 先确认主体生产清单

剧本与制作设定确认后、调用主体创建 Tool 前，先列出本片需要创建或复用的角色、状态和固定场景：

| 主体   | 类型                           | 上游依赖     | 使用范围             | 必要性                 | 原因                 | 决定                     |
| ------ | ------------------------------ | ------------ | -------------------- | ---------------------- | -------------------- | ------------------------ |
| {名称} | {基础角色、衍生状态或固定场景} | {无或主体名} | {对应 Scene 或 Shot} | {必须、建议或文字足够} | {独立保持一致的原因} | {创建、复用、合并或删除} |

只把跨多个镜头复用，或身份识别依赖该外观的换装、年龄、受伤和变异状态作为独立角色主体。轻微表情、短暂污渍、普通持物和单镜头变化保留在 Shot 与 Frame，不增加主体。

血缘亲属、年龄变化、换装、受伤和变异状态形成有向依赖。先确认基础角色，再处理衍生主体。实时 schema 没有正式字段绑定上游图片资源时，不得声称实现了图片级身份继承；只能复用文字身份锚点并明确一致性风险。缺少该绑定会实质影响任务时，报告 MCP 能力缺口并停止受影响主体的生成。

主体生产清单在剧本与制作圣经确认后单独展示，作为「资产清单确认」门禁；分镜方案确认前可以创建已经确认的主体结构，但不得编写最终镜头提示词。用户已明确授权全部创作内容自主执行时，可按「必须」项继续，但仍要把最终清单写入 Script 的制作设定。

按 [制作圣经与镜头工作台](production-bible-and-shot-workbench.md) 为每个主体补充固定描述、状态版本、使用范围、参考 Frame 和验收状态。已经用于成片的基础版本不得被新的换装、伤势、天气或破坏状态覆盖。

## 按 schema 选择角色音色

先检查 `createSubject(kind="character")` 的实时 schema。只有 `voiceProfileId` 为必填，或本次任务明确需要为角色配置声音时，才调用 `listSystemVoices`：

1. 根据角色年龄、性别表达、气质和语言搜索；
2. 从服务端结果中选择最匹配的音色；
3. 保存真实明文 ID；
4. 没有合适音色时向用户说明可选项，不编造 ID。

实时 schema 不要求音色且本轮不生成角色声音时，不为主体强制添加音色依赖。schema 要求该字段时必须使用服务端真实 ID，缺少合适音色就停止角色主体创建，不编造或静默省略。

## 编写角色参考图提示词

正视图与三视图都用于角色一致性，不写剧情场景、表演动作或临时情绪。角色手中不持关键道具；道具使用商品主体或独立登记，避免把持物固化到所有镜头。

先固定角色设定：

```text
年龄段
国籍、族裔与成长地域
身高、骨架、肌肉或脂肪分布与重心
脸型、眉弓、眼窝、鼻梁、颧骨、下颌与五官比例
肤色、毛孔、细纹、伤疤和生活痕迹
发型、发色、发际线与发质
基础服装的颜色、层级、剪裁、材质、磨损和污渍
鞋履、固定配饰、左右非对称和身份道具
职业、经历和人物变化形成的姿态与气质
视觉风格
```

从这些设定中选出 5 到 8 个可见的身份锚点。正视图、三视图和所有 Shot 必须使用完全相同的锚点措辞，包括体型比例、辨识度最高的五官、发型、服装颜色、剪裁、材质和固定配饰。不要用「好看」「高级」「电影感」「8K」替代可见特征。

### 正视图

推荐结构：

```text
{具体媒介、材质和成像规则}，角色设定图，{年龄、族裔、骨架、体型比例与重心}，
{眉弓、眼窝、鼻梁、颧骨、下颌、肤质、发际线与发型锚点}，
穿着{固定颜色、层级、剪裁、材质、磨损、左右非对称和配饰}，
正面全身自然站立，双臂自然下垂，
中性表情，均匀中性棚拍光，不受剧情环境色污染，纯净浅色背景，
人物完整入镜到脚部，皮肤、头发、布料和金属反射符合真实材质，
no text, no watermark, no props, no environment
```

### 三视图

推荐结构：

```text
{与正视图完全相同的媒介、色板、光线和成像规则}，同一角色标准三视图，
依次展示正面、侧面、背面，{逐字复用正视图的年龄、体型、五官、发型、
服装颜色、剪裁、材质和固定配饰锚点}，
三个人物比例一致、服装一致、发型一致，中性站姿和中性表情，
均匀棚拍光，纯净浅色背景，角色设计表，细节清晰，
no text, no watermark, no scene, no action
```

不要在三视图中改变服装、年龄、发型、身体比例或面部比例。剧情中的湿衣、伤痕、伪装等临时状态写入具体镜头，不写进基础主体。

提示词必须让不同角色具有可辨识的骨相、生活痕迹和体态，不能只通过发型或服装区分。角色主体使用中性光保存固有色，剧情光线只进入具体 Shot Frame。

## 创建角色结构

按实时 schema 调用 `createSubject(kind="character")`。下面是创建基础形象与三视图计划的参数模板，替换占位值；音色字段仅在需要时加入，不把括号说明当作 ID：

```yaml
projectId: 项目接口返回的原始字符串
idempotencyKey: 本次创建操作的稳定唯一键
kind: character
label: 角色精确名称
voiceProfileId: 服务端返回的真实音色 ID（schema 要求或本次需要时）
frontView:
  content: 最终正视图提示词
threeView:
  content: 最终三视图提示词
```

生成与状态查询按 [MCP 执行协议](mcp-execution.md) 及实时工具定义执行；每次新付费范围独立确认，回读真实媒体文件。

调用将正式主体写入资产库并建立画布应用节点与可选图片计划，不自动生图。分别保存 elementId（主体库记录）、subjectNodeId（画布节点）、generationNodeIds 与 assetTaskPlans；未请求生成计划时 generationNodeIds 可以为空，不以此判断建档失败。回读确认 subjectNodeId 关联返回的 elementId，正式主体属于当前项目。

- 要新出三视图时，必须提供 frontView 计划或真实可复用的基础形象。仅传 threeView.content 不足；frontView 和 threeView 只接受当前 Schema 的字段，不把模型、fileRef 或 generationParams 塞进其中。
- 复用已有演员时，先读取可访问的演员及素材。当前 actorId 是来源演员 ID，referenceAssetIds/threeViewAssetIds 是该来源的素材 ID；不能拿普通上传文件 ID、画布节点 ID 或别的角色素材 ID 代替。三视图复用只选已预览确认的三视图素材。
- 用户给了本地照片或已有成图：按上传流程取得真实 fileRef，通过 Schema 支持的节点 fileRef 挂载或 referenceResources 引用。已有图片直接挂载不调用 generateNodes；照片用来新生成角色图时按费用授权执行。文字“沿用已有图”不会上传或绑定文件。
- 图片节点挂载成功后，还要精读正式主体 assets，确认图片已成为可引用素材。普通子 Frame 的 parentNode 归属只说明排版，不能代替主体素材归档证据；能力不足时报告待绑定，不假称完成，不为修复挂载重复生图。

生成后服务端自动归档主体素材，再用完整主体读取核验。建档、参考图就绪、视觉通过分别记录。

## 识别场景主体

满足任一条件时通常创建场景主体：

- 在多个 Shot 中反复出现；
- 承载开场、转折或高潮；
- 有固定建筑、陈设、地形、光线或色彩要求；
- 后续画面需要稳定引用该空间。

以下内容通常不建主体：

- 一次性普通背景；
- 无固定结构的过渡空间；
- 梦境闪白、纯色虚化等抽象意象；
- 角色特写中不可辨识的背景。

## 编写场景内容

### `sceneDescription`

面向项目编辑者说明：

- 地点和用途；
- 空间结构与前中后景；
- 3 到 5 个关键视觉元素；
- 时间、天气、光线与色调；
- 整体氛围；
- 后续镜头必须保持的连续性细节。
- 出入口、窗户、主要家具和关键道具的固定位置；
- 人物主要站位、移动路线和对话视轴；

### `imagePrompt`

场景参考图必须是无人环境图。推荐结构：

```text
{具体媒介、色板和成像规则}，{广角或中景构图}，{室内或室外空间结构}，
前景{元素}，中景{核心建筑或陈设}，背景{地形或空间延伸}，
{出入口、家具和关键道具的固定位置}，{关键材质与年代特征}，
{主光方向、软硬、色温与明暗关系}，
{氛围}，环境细节清晰，空间关系准确，
no people, no characters, no figures, empty scene, no text, no watermark
```

不要在环境参考图中写人物动作、人物状态或剧情事件。

同一场景的 `sceneDescription`、参考图、Shot 和 Frame 必须复用相同的空间图。场景参考图只展示无人基准空间；人物路线和视轴写入描述，供后续分镜使用。

重复或关键场景先按 [场景设计与连续性](scene-design-and-continuity.md) 完成场景设计卡和参考视图覆盖计划。参考图要服务于后续机位，并留下可在不同视角识别的稳定地标，不只生成正对空间的壁纸式画面。当前主体的基准 Frame 是主建立视图；反向、表演区或状态变化视图使用 `createNode` 创建为同一场景 `element` 的额外子 Frame。

## 创建场景结构

按实时 schema 调用 `createSubject(kind="scene")`，传入：

```yaml
projectId: 项目接口返回的原始字符串
idempotencyKey: 本次创建操作的稳定唯一键
kind: scene
label: 场景精确名称
sceneDescription: 面向编辑者的完整说明
imagePrompt: 最终场景参考图提示词
descriptionLabel: 场景描述
frameLabel: 场景图
```

生成与状态查询按 [MCP 执行协议](mcp-execution.md) 及实时工具定义执行；每次新付费范围独立确认，回读真实媒体文件。

调用只创建场景主体、描述节点和 Frame 结构，不自动生图。收集真实场景主体 ID 和场景 Frame ID，并回读主体列表与画布。缺少主体、描述或 Frame 中任一项时，不得宣称场景主体已完整创建。

需要多张场景参考图时，在取得 subjectNodeId 后按 createNode 的完整 Schema（包括 projectId、idempotencyKey）调用。每张额外 Frame 都把 parentNode 设为同一个场景的 subjectNodeId，例如：

```yaml
nodes:
  - clientRef: scene-reverse
    type: frame
    label: 反向视图
    parentNode: 场景的 subjectNodeId
    content: 最终无人环境图提示词
  - clientRef: scene-performance-area
    type: frame
    label: 关键表演区
    parentNode: 场景的 subjectNodeId
    content: 最终无人环境图提示词
```

正式主体先由 createSubject 建档，额外 Frame 再指向返回的 subjectNodeId。parentNode/parentNodeRef 只表示容器内嵌关系，不替代主体库登记或素材归档，也不要替换成 parentIds/parentRefs。写入后同时核对排版归属与正式主体 assets，只有真实归档的图片才作为主体提及的素材依据。

## 商品主体边界

商品主体也用于承载需要跨镜保持一致的叙事道具，不限于商业商品。候选物只有在反复出现、参与关键动作、承担信息揭示，或具有必须保持的文字、尺寸、缺口、方向和状态时，才提升为独立商品主体。普通场景陈设留在场景锚点；一次性手持物写入具体 Shot 和 Frame。

为入选道具固定：戏剧功能、尺寸级别、材质、3 到 5 个可见锚点、文字方向、握持位置、当前持有人、适用场景和状态变化。参考图使用中性背景并避免人物或手部污染；需要不同状态时，把状态图作为同一商品主体内的额外参考 Frame，并明确母状态与变化项。

正式道具通过 `createSubject(kind="scene", subjectType="prop")` 建档，另带 projectId、idempotencyKey、label 和 sceneDescription；要准备参考图计划时加 imagePrompt。这里 scene 是 API 的非角色分支，不表示把道具当作环境；图像内容仍是独立道具参考图。自定义主体（如色卡）使用该分支的 subjectType="custom" 与 subjects.subjectTypes 返回的真实 subjectTypeId。以实时 Schema 为准，不传 kind="prop" 或 kind="custom"。

先复用已有正式道具，否则创建后分别保存 elementId 和 subjectNodeId。额外基准、三视图或状态 Frame 的 parentNode 指向 subjectNodeId；跨图参考使用接口真实支持的资源字段。回读节点归属、正式主体 assets 和参考图，不能只凭 subjects.product 分组或 subType 判断归档成功。

旧版 `createNode(type="element", subType="product")` 可能仍能建画布容器，但不能作为正式主体创建成功的证据。已有旧节点先检查关联和素材，再决定是否需要建档；保留旧图和版本，不自动删除或重生。当前部署缺少正式道具分类或素材绑定能力时，报告具体缺口，不随意猜新 Tool、枚举或 ID。

## 生成主体参考图

本节是完整成片的资产锁定阶段。确认后的唯一 Script 必须已经写入并回读；不要求任何 Scene、Shot、Frame、Video 或 Audio 子树已经创建。角色、场景和商品主体结构完成各自写入与 FULL 回读后：

1. 按生产清单分别汇总各依赖层的角色与商品正视图、必要的角色与商品三视图，以及场景图 Frame ID；
2. 重新读取 FULL 画布快照和主体列表，确认每个 Frame 的 `content` 与主体归属，并保留主体 Tool 对生成配置的 schema 校验和成功响应；
生成与状态查询按 [MCP 执行协议](mcp-execution.md) 及实时工具定义执行；每次新付费范围独立确认，回读真实媒体文件。
生成与状态查询按 [MCP 执行协议](mcp-execution.md) 及实时工具定义执行；每次新付费范围独立确认，回读真实媒体文件。
5. 在可信项目页面验收本层角色与场景。检查身份锚点、年龄骨相、完整脚部、服装层级、左右非对称、固有色、材质反射和固定空间结构；生成成功或用户上传图片都不等于定稿，必须取得明确确认；
6. 若生产清单还有依赖已确认上游的角色或状态正视图，按依赖层重复步骤 3 至 5；实时 schema 要求绑定上游资源时，必须使用真实已确认资源，不能只写继承措辞；
生成与状态查询按 [MCP 执行协议](mcp-execution.md) 及实时工具定义执行；每次新付费范围独立确认，回读真实媒体文件。
8. 只有全部必需主体 Frame 同时具有文件证据和视觉确认后，才创建或生成依赖这些主体资源的试拍与正式 Shot Frame；
9. 最后回读 FULL 画布和主体列表。

生成与状态查询按 [MCP 执行协议](mcp-execution.md) 及实时工具定义执行；每次新付费范围独立确认，回读真实媒体文件。

不要在生成调用中重复传入 Prompt、模型或参考资源。主体工具已经创建的节点配置是服务端生成计划的输入；缺失必需配置时先停止。只有实时 schema 提供正式字段时才能通过节点写入能力补齐，否则报告 MCP 能力缺口。

主体参考 Frame 不能与依赖它们的 Shot Frame 放进同一个生成计划。第一版跨节点产物绑定只支持 Frame `PRIMARY` 到直接下游 Video `FIRST_FRAME`，不支持 Frame 到 Frame。主体参考图必须先取得成功终态并通过视觉验收，后续才能创建依赖该版本的 Shot Frame，或生成已经存在的依赖节点。

主体参考图没有成功终态，或 FULL 快照中的 `frameFiles` 为空时，不把该主体描述为已具备可用视觉参考，也不生成依赖它的 Shot Frame。`status="COMPLETED"` 不能代替文件检查。聚合结果为 `PARTIAL_FAILED` 时保留成功项，不自动再次提交失败节点；返回项目入口并由用户决定后续处理。

视觉验收失败时从当前确认的制作设定重新形成受影响提示词，只修改失败来源。不要在旧提示词末尾追加「保持一致」「不要改变」等历史补丁。Agent 无法查看媒体像素时，明确请求用户完成视觉确认，不根据文件存在推断质量。
