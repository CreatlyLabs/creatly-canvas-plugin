# 制作圣经与镜头工作台

## 目标

把已经确认的剧本转换为可复用的制作常量、可验收的资产版本和可审计的镜头版本。核心原则不是增加提示词长度，而是减少每次生成时由模型重新猜测的内容。

本文件只定义创作方法。节点类型、模型参数、参考资源绑定、生成模式和付费流程仍以实时 MCP schema 为准。某个模型要求纯文生视频、特殊标签、音频参考或专用批次语法时，只有 `listGenerationModels` 与节点写入 schema 明确支持后才能采用。

## 建立制作圣经

「制作圣经」指本项目后续节点共同复用的制作规则集合，不是额外的节点类型。细版剧本形成后，先整理以下内容，并与剧本一起确认，再拆最终 Shot：

```text
世界常量：国家、地域、年代、季节、技术与物件边界
视觉常量：媒介、色板、材质、光线、镜头家族、后期质感
声音常量：环境声、对白语言、口音条件、语速、音乐使用边界
角色常量：身份锚点、行为基线、声音基线、状态版本
场景常量：空间图、稳定地标、主光方向、允许机位、状态版本
道具常量：尺寸、材质、文字方向、握持位置、损坏状态
连续性常量：角色、服装、伤势、道具、天气和空间的状态顺序
禁止项：超出年代、世界规则、授权范围或视觉规则的元素
```

固定内容使用短而明确的「常量块」。后续节点逐字复用适用部分，不用「同前」「保持一致」「沿用上一镜」代替。生成模型没有项目记忆，当前 Shot 必须独立说明本镜可见和可听的事实。

## 建立资产登记表

每个需要跨镜保持一致的角色、场景和商品主体建立一条资产记录：

| 字段              | 要求                                            |
| ----------------- | ----------------------------------------------- |
| `assetName`       | 与画布主体 Label 一致的唯一名称                 |
| `assetType`       | 角色、场景或商品主体                            |
| `fixedDescriptor` | 5 到 8 个稳定可见锚点或稳定空间锚点             |
| `stateName`       | 基础、换装、受伤、雨后、损坏等明确状态          |
| `version`         | `v1`、`v2` 等独立版本，不覆盖已用于成片的旧版本 |
| `usage`           | 使用该版本的 Scene 或 Shot                      |
| `referenceFrames` | 当前主体内真实存在并已确认的参考 Frame          |
| `acceptance`      | 未生成、待验收、通过、拒绝                      |

基础角色与叙事状态分开。只有会改变跨镜识别的换装、年龄、伤势或变异才创建独立状态主体；轻微表情和一次性污渍留在 Shot。角色参考图中的手保持空闲，关键道具单独登记，避免把道具错误固化到所有镜头。

重复场景的参考图要服务于未来机位，不只生成正面壁纸式画面。主建立视图至少留下一个稳定地标，并在反向视图、关键表演区和 Shot blocking 中使用同一空间图。不同时间、天气或破坏状态使用独立版本，不覆盖原始场景。

## 资产生成与验收

按依赖顺序先生成资产，再生成镜头：

1. 无依赖的角色基础正视图、场景主建立视图和必要商品主体；
2. 角色三视图、场景反向视图与关键表演区；
3. 依赖基础资产的角色或场景状态版本；
4. 代表 Shot Frame；
5. 代表 Video；
6. 剩余镜头。

角色参考图使用中性背景、柔和均匀光和真实材质，不使用会污染剧情镜头的轮廓光、夸张顶光或环境色。需要对白特写的主要角色，可在实时主体结构支持时增加中性闭嘴与自然开口参考；不支持时不伪造新主体字段。

每个资产版本必须同时满足媒体文件证据和视觉验收。验收失败时只修改该资产的真实失败来源，并创建新版本或更新尚未被采用的版本；不要在旧提示词末尾不断追加补丁。

## 编写镜头卡

导演分镜与试拍确认后，先为代表 Shot 所在的试拍 Scene 形成完整镜头卡。试拍通过后，再逐 Scene 编写其余镜头卡，不提前编译全片最终提示词。镜头卡不是镜头名称列表，至少包含：

```text
镜头 ID 与所属 Scene
叙事目标：本镜让观众新知道或新感受到什么
人物任务：角色此刻要对谁做成什么
阻力与代价：什么阻止角色，失败会失去什么
策略与变化：角色采用什么动作策略，何时改变策略
可见表演：视线、呼吸、姿态、手部任务、停顿和反应
空间：人物、道具、地标、摄影机和运动路线
摄影：景别、机位、焦段或视场倾向、单一运镜
素材：角色及状态、场景及状态、商品主体、台词和声音
时序：动作拍、逐字台词、时长、首帧和结束状态
剪辑：进入方式、离开方式、节奏和下一镜衔接
复杂度：简单、中等或复杂
```

表演写行为，不直接要求角色「表现愤怒」「非常悲伤」。优先写角色的目标、阻力、策略、身体任务和可见反应。例如把「她很紧张」转换为「她继续叠衣服，听到名字后手指停住半秒，先看门口再回答」。对白前后的思考、聆听和反应要可见，不能让人物只等轮到自己说话。

## 执行镜头审计

镜头卡通过审计后才能编译最终 Frame 和 Video 提示词。逐镜检查：

- 首帧是否已经包含全部必需主体和可读空间关系；除非有明确叙事理由，不以空画面或无关定场开头；
- 当前 Shot 是否残留上一镜的角色、主体 Mention、场景编号或旧提示词片段；
- 左右位置、朝向、视线、摄影机侧、地标距离和道具持手是否明确；
- 场景参考只提供地理、材质和光线依据，是否被误当成必须复制的构图；
- 焦段、机位和内容是否匹配，是否同时要求互相冲突的透视或运镜；
- 动作是否符合重量、接触、惯性、衣料、液体和环境物理；
- 台词字数、动作拍和时长是否匹配，是否给反应和剪辑留下时间；
- 固定描述与当前状态是否来自制作圣经和资产登记表；
- 复杂度是否超过单次生成可稳定完成的范围。

发现风险时，在对应位置加入短而具体的约束，不堆积统一的长负向列表。需要数量、距离、大小、朝向或节奏时，使用可观察证据：画面占比、与地标的相对位置、明确数量、动作发生时间或失败判定。

## 编译提示词

最终提示词由当前镜头卡编译，不从上一镜提示词复制后改写。推荐顺序：

```text
本镜事件与戏剧背景
当前有效主体与状态
首帧占位和空间关系
景别、机位、焦段或视场倾向
动作与表演节拍
物理和材质变化
光线与曝光
对白、环境声和音乐边界
连续性与局部失败约束
```

比例、分辨率、模型、时长和生成模式属于平台参数时，只写入实时 schema 对应字段，不在自然语言提示词中重复。主体 Mention 只包含本镜真实出现或必需的主体，不引用未出镜资产。

当前系统以 Frame 作为 Video 首帧时，Video 必须从父 Frame 的人物姿态和空间状态继续。若实时模型支持无首帧的纯文生视频，可按该模型的正式能力单独设计；不能把其他平台「只用文本与参考图」的规则强加给当前模型。

## 镜头工作台

每次试拍保留一条简短记录：

```text
shotId
promptVersion
sourceNodeId
generationRef
result：通过、拒绝或失败
observedProblem：只写可观察问题
changedVariable：本版唯一主动修改项
verdict：保留、继续试验、拆镜或改变拍法
```

一次试验只改变一个主动变量，例如主体版本、首帧站位、镜头焦段、动作拍、运镜或局部提示词。其余固定块逐字保持。若同时改变多个变量，无法判断哪项有效，本次试验不进入扩量依据。

镜头连续失败时不要无限改写措辞。约 3 次仍是同类可观察问题，或 15 到 20 次仍无法得到可用镜头时，重新评估制作方法：

1. 把复杂动作拆成准备、接触和结果；
2. 让高复杂动作从已经发生的状态开始，把接近过程放到上一镜；
3. 删除不承担叙事作用的动作、群演或运镜；
4. 改变机位、景别或遮挡方式，从可稳定生成的角度呈现结果；
5. 使用插入镜头、反应镜头、画外声或剪辑表达无法稳定生成的事件；
6. 实时模型支持合规动作参考时才采用，否则报告能力缺口。

改变拍法会影响 Shot、Frame、Video 或剪辑计划时，回到导演分镜与试拍确认边界，不把它伪装成局部提示词修订。

## 并行剪辑与成片检查

已通过的 Scene 可以先进入 Preview 检查节奏，但不得把局部 Preview 描述为整片完成。检查时记录需要补拍的反应镜头、远景、插入镜头和声音过渡，再按明确范围回到镜头工作台。

最终检查优先处理：

1. 人脸、手部和关键道具错误；
2. 身份、服装、空间和光线漂移；
3. 动作物理、视线和连续性；
4. 镜头节奏、环境声连续和色彩统一；
5. 不影响叙事的轻微纹理问题。

真正损坏的镜头从保存的可用版本重新生成，并只修改一个变量。不要让后期修补替代资产、空间或动作设计错误。
