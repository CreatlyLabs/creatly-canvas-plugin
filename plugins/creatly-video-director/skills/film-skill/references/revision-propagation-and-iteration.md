# 修改传播与镜头迭代

判断一次修改波及哪些节点，以及一个镜头反复不达标时如何收敛。两者都是创作方法：结论在任何宿主上都相同，与项目页面如何打开无关。恢复流程本身（从 FULL 快照重建、判断中断位置、幂等重放）属于宿主执行细节，见 Host 侧的 `revision-and-recovery.md`。

## 计算修改传播范围

### 修改 Script

判断变化是否影响角色、场景、Scene、Shot、Frame、Video、Audio 或 Preview。只改错别字且不改变表演时，不改下游；改变情节、人物、动作、台词或时长时，先列出受影响节点范围。

### 修改 Shot

景别、动作、主体、光线或时长变化通常影响对应 Frame 和 Video。台词变化还影响 Script 和 Audio。先整理可以安全提交的原子更新集合：

```text
Script（如需） + Shot + Frame + Video
```

Audio 变化单独判断。修改文案、Edge 或 TTS 配置时，把 `content`、`parentIds` 和实时 schema 支持的 `generationParams` 放入同一原子 `updateNode`；未暴露必需配置字段时报告能力缺口，不执行破坏性近似更新。只改 Label、顺序、嵌套或布局时按实时 schema 提交，不把这些字段解释为生成配置。

### 修改 Frame

Frame 表示 Video 首帧。Frame 内容或配置变化时，检查对应 Video 的起始状态和生成计划是否也需更新。只保存文本不自动生成。

### 修改 Video

只更新目标 Video 时保留父 Frame，并确认新提示词仍从当前 Frame 自然开始。不要修改范围外的 Shot、Frame 或 Preview。

## 控制镜头迭代

质量问题按 [制作圣经与镜头工作台](production-bible-and-shot-workbench.md) 记录 `shotId`、提示词版本、Node ID、`generationRef`、可观察问题、唯一主动修改项和结论。一次再次生成只改变一个主动变量；其他已经确认的制作常量和镜头卡字段保持不变。

先修改最上游的真实原因：

- 身份或服装漂移，回到主体资产版本；
- 空间或地标错误，回到场景资产和 blocking；
- 首帧构图错误，修改 Frame；
- 动作、表演或运镜错误，修改 Video；
- 镜头任务过载，修改 Shot 并重新确认受影响的分镜方案。

同类可观察问题约 3 次仍未改善时，停止同义改写，重新判断主体、空间、动作和模型能力。长期试验仍不可用时，拆动作、删除次要内容、改变机位、使用反应镜头或画外声表达结果。改变拍法影响叙事、节点结构或付费范围时，回到对应创作确认点；不把它当作普通再次生成。
