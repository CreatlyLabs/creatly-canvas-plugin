# 场景设计与连续性

## 目标

把场景从一段氛围描述变成可复用的制作资产，并让角色、道具、空间、时间和光线在连续镜头中保持可验证的一致。本文件只规定创作和节点配置方法，不改变实时 MCP schema。

## 先建立场景设计卡

先从剧本提取场景名册，再决定哪些空间值得成为主体。反复出现、承担开场或转折、需要固定空间关系的场景提升为场景主体；一次性普通背景优先复用已有空间，通过时段、天气、前景或陈设变化形成变体，不为每次地点变化都创建新主体。

变体必须记录母场景和明确变化项。门窗、主要家具、固定材质、空间尺度和方向关系默认继承；只有剧情实际发生破坏、搬移或改造时才改变。若新场景与母场景没有可复用的空间锚点，就创建独立场景主体，不强行复用。

每个重复出现或承担关键剧情的场景，在创建主体和拆 Shot 前先形成一张场景设计卡：

| 维度         | 必须固定的内容                                               |
| ------------ | ------------------------------------------------------------ |
| 叙事功能     | 本场景承载的信息、冲突、转折或情绪作用                       |
| 空间骨架     | 出入口、窗户、墙面、主要家具、关键道具及彼此方向             |
| 深度分层     | 前景遮挡、中景表演区、背景延伸和视觉终点                     |
| 人物调度     | 主要站位、移动路线、停点、朝向和对话视轴                     |
| 光线         | 主光来源、方向、软硬、色温、环境光和阴影方向                 |
| 材质与年代   | 建筑、地面、家具、织物、金属及磨损状态                       |
| 色彩         | 固有色、允许的环境色、禁用色和颜色承担的叙事作用             |
| 时间与天气   | 季节、昼夜、天气，以及进入和离开本场景时的状态               |
| 固定锚点     | 每个机位都应保留的 3 到 6 个可见空间特征                     |
| 禁止漂移项目 | 不能改变的门窗数量、家具方向、道具位置、光源方向和空间尺度等 |

设计卡的最终内容进入 Script 的制作设定、场景主体描述和相关 Shot，不只留在聊天中。

## 规划场景覆盖

先按剧情需要规划参考视图，不机械追求图片数量：

1. **主建立视图**：清楚交代空间骨架、深度和主光，作为场景主体的基准图；
2. **反向或侧向视图**：只有镜头确实跨越主视角或需要反打时才规划；
3. **关键表演区视图**：只覆盖人物长期活动、关键道具交互或高潮动作所在区域；
4. **状态变化视图**：只有破坏、天气、昼夜或陈设发生持续变化时才单独规划。

每张参考图必须说明解决什么连续性问题。两个视图不能在门窗、家具、道具、光源和左右关系上互相冲突。

`createSubject(kind="scene")` 创建正式场景主体、画布应用节点及可选参考图计划，不限制只能有一张参考图。额外 Frame 的 createNode.parentNode 指向返回的 subjectNodeId（不是 elementId）；多个 Frame 可以共用该容器。排版内嵌不等于素材已归档：作为主体提及参考前，按 [主体创建](subjects.md) 回读正式主体 assets 核对。

嵌套归属与生成依赖必须分开表达：`parentNode` 和 `parentNodeRef` 表示节点位于哪个 `element` 内；`parentIds` 和 `parentRefs` 只表示 Edge 关系。不要用 Edge 代替主体内嵌关系。额外 Frame 创建后必须回读 FULL 快照，确认其归属，再按生产顺序生成和验收；不伪造节点或用聊天图片代替。

## 建立场景资产清单

对每个可用场景参考 Frame 记录：

```text
场景精确名称
参考 Frame nodeId
视图用途：主建立 / 反向 / 表演区 / 状态变化
覆盖的空间锚点
适用的 Scene 与 Shot
时间、天气和破坏状态
视觉确认状态
```

只有同时满足以下条件的 Frame 才能进入资源绑定：

- 属于当前项目；
- FULL 快照中具有非空 `frameFiles[].fileId`；
- 画面经过可信页面视觉确认；
- 与当前 Shot 的时间、天气、空间和破坏状态兼容。

## 编制连续性矩阵

写 Frame 和 Video 提示词前，为全部 Shot 建立矩阵：

| Shot | 角色身份 | 服装与身体状态  | 道具与持有人 | 空间与朝向  | 时间与光线 | 动作进出点  | 转场依据 |
| ---- | -------- | --------------- | ------------ | ----------- | ---------- | ----------- | -------- |
| S01  | {锚点}   | {进入/离开状态} | {位置/方向}  | {站位/视轴} | {状态}     | {起点/终点} | {接法}   |

逐行检查：

- 下一镜进入状态能从上一镜离开状态得到；
- 同一角色的基础身份锚点不因情绪、机位或景别改变；
- 状态变化必须有发生镜头，不能在切镜后无原因出现；
- 道具的左右方向、握持手、当前位置和损坏程度保持一致；
- 反打镜头保持视轴，越轴必须有可见的过渡依据；
- 同一空间的门窗、家具、光源方向和人物路线保持一致；
- 时间、天气和环境破坏只沿剧情允许的方向变化。

矩阵是生成前的内部检查工具。其有效结论写入 Shot 的 `continuity` 和 `transition`，不要求把整张表写入画布。

## 跨段连续性（生成单元之间）

一段视频（生成单元）由模型独立生成，段与段之间不会自动继承场景、人物状态和道具。下一段开生成前，先从上一段**实际生成的成片**里取状态，而不是从设定图里推：

1. **垫上一段的状态帧。** 从上一段成片抽出与下一段开头最接近的一帧（原画质，不用截图），作为「上一段结尾状态」参考图：锁定人物站位、服装、手持道具、场景和光线，不锁定机位。用户指定某一帧时用那一帧。
2. **反复出现的群众和配角，垫之前成片里的帧。** 没做成主体的人群、配角，每次生成都会换成另一批人；在新一段里再次出现（反打、主观视角、插入镜头）时，观众会觉得「换了一波人」。从之前已认可的成片里抽 2–3 张这群人的原画质帧（覆盖前排主要面孔和服装），垫进新的生成，职责写「前一段里的同一群人：锁定长相、年龄、发型、服装和质感，画面里就是这些人」；文字里再点名前排几个人的特征（如抱孩子的母亲、白发老人、黑卷发青年），服装和色调照帧写死，禁止「换成另一群人」。反复出现的面孔考虑升级为主体。
3. **状态写成文字，不只靠主体 @。** 主体参考锁脸，服装和道具会在不同生成之间漂移，必须在提示词里逐项写死并声明「全段不变」：
   - 服装：每个出场角色的颜色、款式、层次、条纹或纹样、腰带；
   - 道具：谁拿、哪只手、朝向（如杖头弯钩朝上）、高度，「不松手、不换手、不举起、不放下」；
   - 站位：谁在谁的画左 / 画右、前后关系，「不换边」；
   - 光线：光源方位、时间、受光面，与上一段一致。
4. **场景参考要和人群状态一致。** 开场就有人群时，垫「已经站满人」的场景图；垫空场景图再写「人群出现」会让人从空地和阴影里凭空长出来。人物只能从有依据的地方进出（帐篷门口、画外）。
5. **插入镜头要垫前后两镜控色。** 要剪进两个已生成镜头之间的新镜头，把前一镜的最后一帧和后一镜的第一帧（原画质）都垫进去，参考职责写「只锁调色：受光色温、天空与海面的颜色、饱和度、亮度，放在中间看不出跳变」；风格或构图参考图的职责里写明「不锁色调」。色卡 HEX 只能定大方向，相邻镜头的真实画面才能把调色对齐。
6. **参考图里的道具姿势会被照抄。** 构图参考图里如果手持道具的握法、朝向不对（如握反了牧杖），即使职责里写「不锁定道具姿势」，模型仍会照搬。先用图片模型只修改参考图里的这一处（其余保持不变），再用修好的图做参考。
7. **不要跨生成拼接同一段。** 两次生成的服装、音色、环境声都会不同。某段个别镜头有问题时改提示词整段重生成；只在用户明确要求时补短镜头替换——补拍画面要按第 2、5 条垫前段帧和前后镜控色，并保留原段音轨（画外音、环境声不断）。
8. **生成后逐帧核对上一段的离开状态和这一段的进入状态**：服装、道具的手和朝向、站位左右、光向。发现漂移，把漂移项补进文字锁定后重生成。

## 编译最终提示词

Frame 提示词按以下来源顺序编译：

```text
全片视觉规则
+ 角色基础身份锚点
+ 当前服装、伤势、污渍和道具状态
+ 场景设计卡与当前参考视图锚点
+ Shot 的视觉目的、调度、构图、机位和焦段
+ 连续性矩阵的进入状态
+ t=0 动作预备状态
```

Video 提示词继承同一组来源，再加入动作时间线、单一运镜、离开状态和转场余量。上游规则冲突时回到最高层有效设定修正，不能在提示词末尾追加相互矛盾的补丁。

## 绑定多张场景参考图

实时 `updateNode` schema 暴露 `generationParams.referenceResources` 时，可为 Frame 或 Video 写入有序的 `PARENT_NODE` 资源：

```yaml
generationParams:
  referenceResources:
    - mediaType: IMAGE
      role: REFERENCE
      sourceType: PARENT_NODE
      sourceNodeId: 场景主建立 Frame ID
    - mediaType: IMAGE
      role: REFERENCE
      sourceType: PARENT_NODE
      sourceNodeId: 当前机位对应的补充 Frame ID
```

顺序从最重要、最贴近当前 Shot 的参考开始。只绑定当前镜头真正需要的视图，避免互相冲突的参考图同时进入生成。

`dimensions.width` 和 `dimensions.height` 只控制画布卡片大小。生成图片规格使用 `generationParams.ratio`、`aspectRatio` 和 `resolution`；具体值必须来自本轮 `listGenerationModels` 返回的对应模型能力。

若实时 Tool schema 未暴露 `generationParams`，或资源不是当前项目中的 `PARENT_NODE`，停止受影响的生成并报告能力缺口。

## 生成前检查

- 场景设计卡与 Script 制作设定一致；
- 参考视图之间的空间骨架和光线没有冲突；
- 连续性矩阵覆盖所有相邻 Shot；
- 每个 Frame 和 Video 提示词都能追溯到上游有效设定；
- 多参考资源顺序清楚，且每个来源节点都具有文件证据和视觉确认；
- 生成比例、宽高比和分辨率已写入节点配置，而不是误写到 `dimensions`；
生成与状态查询按 [MCP 执行协议](mcp-execution.md) 及实时工具定义执行；每次新付费范围独立确认，回读真实媒体文件。
