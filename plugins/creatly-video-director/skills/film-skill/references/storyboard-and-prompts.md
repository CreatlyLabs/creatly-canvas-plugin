# 分镜与提示词

## 目标

把 Script 转成可生成的 Scene、Shot、Frame、Video 和可编辑的可选 Audio 结构。分镜负责叙事与连续性，Frame 提示词负责首帧，Video 提示词负责从首帧开始的时间变化。

## 先确定镜头预算

先从 Script 读取已确认的项目制作设定、文字情绪曲线、摄影与声音基准。镜头密度、景别距离、相机稳定程度、动作速度和声音留白必须服务于曲线：上升段逐步收紧，呼吸区允许稳定和停顿，最高点使用最清楚的视觉变化，不靠无依据的快速剪辑制造强度。

进入本文件前，故事方向、完整剧本、制作圣经和资产版本必须已经确认，必需主体参考图必须通过视觉验收。先只形成全片 Scene 与 Shot 方案，向用户展示：镜头顺序、每镜唯一叙事作用、预计时长、景别、主要动作、复杂度和转场，然后结束当前回复等待确认。取得明确的「导演分镜与试拍确认」后，先为代表 Shot 所在 Scene 编写 `visualPurpose`、`blocking`、`composition`、最终 Frame、Video 和 Audio 提示词；试拍通过后再逐 Scene 编写剩余内容。用户明确授权全部创作内容自主执行时可以连续处理，但必须完成同样的分镜与试拍检查。

初始镜头数按以下公式估算：

```text
目标镜头数 = 目标总时长秒数 / 5，向上取整
```

再根据场景时长、对白量、关键动作、情绪转折和信息揭示分配 Shot。

允许单 Shot 的场景仅限：

- 约 6 秒以内；
- 只有一个信息点；
- 只有一个简单动作或一条短台词；
- 用作过渡、空镜或短暂反应。

包含多轮对白、多个关键动作、情绪转折、关系变化或景别变化的场景必须拆成多个 Shot。

## 判断何时新建 Shot

出现以下变化时通常新建 Shot：

- 地点或时间变化；
- 主要画面主体变化；
- 景别发生明显变化；
- 一个关键动作开始或完成；
- 新信息被揭示；
- 角色的情绪或决定发生转折；
- 需要独立的插入细节或反应镜头。

以下变化通常留在同一 Shot：

- 同一构图内的连续一句对白；
- 表情轻微变化；
- 不改变叙事信息的小动作；
- 可以由一次清楚运镜完成的空间展示。

切镜依据是剪辑切换，不是画面内部变化。推拉摇移、主体进出、焦点变化、闪光或速度变化仍可能属于同一个连续 Shot；只有硬切、明确转场或叙事时间跳跃才必然新建 Shot。若根据参考视频拆镜，时间轴必须从开头连续覆盖到结尾，不机械等分镜头时长。

复杂动作按「准备、接触、结果」检查信息是否完整。三个动作拍可以在一个连续 Shot 内完成，也可以根据视角、信息焦点和生成难度拆成多个 Shot；不能只保留接触瞬间，导致动作没有起点或结果。

## 避免过拆与过度合并

定场最多用 1 到 2 个镜头完成。优先用一个带缓推的远景同时交代空间和主体，不连续堆叠无叙事功能的环境细节。

相邻 2 到 3 个镜头若能由真人导演用一次连贯拍摄完成，考虑合并。合并后若单个 Shot 包含多轮对白、多个关键动作或完整起承转合，则拆开。

一镜到底只用于连续位移、跟随、环绕或角度渐变能明显改善叙事的情况。信息持续变化时可超过常规 6 秒，但通常不超过 12 秒。不要为了形式增加生成难度。

## 保持视觉连续性

逐 Shot 检查：

1. 动作连续：下一镜从上一镜结束状态接续。
2. 空间连续：人物、道具和出入口位置符合物理关系。
3. 视轴稳定：对话双方保持在 180 度线同一侧。
4. 朝向合理：人物朝向对方、目标或运动方向，不默认看镜头。
5. 景别有节奏：远到近用于收紧，近到远用于释放；避免连续三个无变化的同景别。
6. 信息受控：每镜明确观众新知道什么。
7. 节拍匹配：2 到 3 秒通常承载一个动作拍；4 到 6 秒承载一到两个动作拍。
8. 状态连续：换装、伤势、污渍、变异和环境破坏符合 Script 中的状态顺序。
9. 道具连续：尺寸、材质、左右方向、持有人、握持位置和损坏状态符合关键道具登记。

关键动作不要放在镜头首尾的瞬间。为入画和收势保留短暂安全区。

完整成片在拆镜前必须已经按 [导演质量控制](director-quality.md) 固定视觉规则、角色身份锚点、场景空间图和连续性账本。分镜负责执行这些规则，不在每个镜头重新发明风格或空间。

重复场景还要读取 [场景设计与连续性](scene-design-and-continuity.md)，先完成场景设计卡、参考视图覆盖和全片连续性矩阵。每个最终提示词必须能追溯到全片规则、主体锚点、当前状态、场景锚点、Shot 设计和动作进出点。

## Shot 内容字段

每个 Shot 在写入画布前形成以下镜头卡字段。完整成片同时读取 [制作圣经与镜头工作台](production-bible-and-shot-workbench.md)：

| 字段            | 要求                                                                |
| --------------- | ------------------------------------------------------------------- |
| `description`   | 15 到 50 字，写可见主体、动作或状态、环境空间，至少体现两个空间层次 |
| `visualPurpose` | 本镜让观众看到、理解或感受到的唯一变化                              |
| `characterTask` | 角色此刻要对谁完成什么，使用可执行动作动词                          |
| `obstacle`      | 阻力、失败代价和迫使策略变化的事件                                  |
| `performance`   | 视线、呼吸、姿态、手部任务、停顿、聆听和反应                        |
| `shotSize`      | 大全景、远景、全景、中景、近景、特写、过肩镜等                      |
| `blocking`      | 人物和道具的站位、朝向及移动路线                                    |
| `composition`   | 主体位置、前中后景、视线空间和唯一视觉焦点                          |
| `cameraAngle`   | 平视、俯视、仰视、过肩等具体机位                                    |
| `lens`          | 焦段或透视倾向，以及选择它的叙事原因                                |
| `cameraMove`    | 静止，或说明推、拉、摇、移、俯拍、仰拍的起点和终点                  |
| `action`        | 连续物理动作链、速度、与上一镜衔接、人物朝向                        |
| `emotion`       | 具体可感的情绪，如「克制而警觉」，不要只写「难过」                  |
| `lighting`      | 主光方向、色温和明暗关系                                            |
| `scene`         | 与剧本和场景主体一致的固定名称                                      |
| `duration`      | 结合动作和对白计算的秒数                                            |
| `lines`         | 从剧本逐字复制的台词；无台词明确写「无台词」                        |
| `sound`         | 环境音层和动作音层；没有则写「无音效」                              |
| `subjects`      | 画面中可辨识的角色和适用场景主体                                    |
| `continuity`    | 从上一镜继承并交给下一镜的位置、动作、道具和状态                    |
| `transition`    | 动作接、视线接、声音接、硬切或其他明确接法                          |
| `complexity`    | 简单、中等或复杂；说明最可能失败的单一因素                          |

Shot 的 `content` 使用易读文本保存这些字段，不要求把内部表格结构直接展示给用户。

`sound` 必须继承全片声音基准，并区分环境声、同步动作声、非语言人声、对白和音乐。不是每个 Shot 都需要音乐；没有叙事作用时保留环境声和必要留白。

`emotion` 只记录观众可感知的状态结果，不能代替表演设计。`characterTask` 使用「迫使对方承认」「拖延检查」「掩饰受伤」等动作目标；`performance` 把压力转换为可见行为。角色有对白时同时设计聆听、思考和回答，不让表情只在台词开始时突然出现。

## 镜头审计

镜头卡编译为最终提示词前逐项审计：

1. 首帧已包含全部必需主体、地标和可读空间关系；没有明确叙事理由时，不以空画面或无关定场开头。
2. 只保留当前镜头出现的主体 Mention、道具、场景和状态，不携带上一镜残留或「同前」等依赖模型记忆的说法。
3. 人物左右位置、朝向、视线、摄影机侧、地标距离、道具持手和运动路线没有歧义。
4. 场景参考提供地理、材质和光线依据，不强迫镜头复制参考图构图。
5. 景别、焦段或视场倾向、机位和内容匹配，只有一个主要运镜。
6. 动作符合重量、接触、惯性、衣料和环境物理，动作拍数量与时长匹配。
7. 台词逐字来自剧本，并为聆听、停顿、反应和剪辑留出时间。
8. 固定描述来自已确认的制作圣经和资产版本，状态与连续性账本一致。
9. 复杂镜头可拆成准备、接触和结果时，优先拆镜，不用更长提示词掩盖超载。

审计风险只在对应位置加入短约束。需要控制数量、距离、大小、方向或节奏时，写画面占比、相对地标、明确数量或发生时间等可观察证据，不堆积抽象画质词。

## 景别选择

| 景别         | 主要用途                     |
| ------------ | ---------------------------- |
| 大全景、远景 | 定场、空间关系、孤独感或规模 |
| 全景         | 角色登场、全身动作           |
| 中景         | 对话、日常叙事、人物关系     |
| 近景         | 情绪和重要对白               |
| 特写         | 面部、手部或关键道具         |
| 过肩镜       | 对话中的空间对立             |

大特写只用于决定性瞬间，不要频繁使用。

## 运镜术语边界

用词必须对应真实摄影机行为：

- 「摇」是摄影机位置不变，只改变朝向；「横移」是摄影机沿水平方向改变位置。
- 「推近、拉远」是摄影机空间位置变化；「变焦」是焦距变化，透视效果不同，不能混写。
- 「仰摇、俯摇」是机位不变的上下转动；「升降」是摄影机高度变化。
- 「跟拍」说明跟随对象、方向和相对距离；「环绕」说明围绕主体的弧线方向与落幅。
- 手持、稳定器、轨道、摇臂或航拍只在媒介和场景支持时使用。

每个 Shot 默认只有一个主要运镜。先写起始机位，再写方向、速度、跟随对象和落幅；没有叙事动机时使用固定镜头。

## 主体引用准备

写最终提示词前，按 [MCP 读取策略](mcp-execution.md#按需读取节点) 精读本镜所需的主体（可用 subjectId/subjectQuery 定位），复用同一版本的已保存回执，不反复拉整张画布。建立精确映射：

```text
主体 Label -> 主体 ID -> subtype -> voiceProfileId（如有）
```

画面中出现的已建主体使用 `[@主体名]`。场景主体适用时也必须引用。一次性普通背景直接描述，不创建或引用不存在的主体。

不要把内部 ID 写进可见提示词。ID 只放在实时 schema 支持的 `mentionElementIds` 或资源参数中。

### 角色参考图（强制）

Frame 与 Video 中出现的每个已建主体（角色、场景、色卡），都必须在提示词里用 `[@主体名]` 提及，由主体图锁定。主体不连线（不写进 `parentIds`），也不重复写进 `referenceResources`，保持画布清爽。角色正视图尚未生成时，先生成角色图。只靠文字描述身份视为未完成。详见 [MCP 执行协议](mcp-execution.md) 的「角色参考图（强制）」。

### 色卡（强制）

分镜 Frame 生成前先有本幕色卡图（暗部 / 中间调 / 高光三档色块 + HEX），做成色卡主体。每个 Frame 和 Video 的提示词加「【色卡】[@色卡] …」一行：只锁定色调、明暗比例和饱和度，不决定构图，并抄录关键 HEX；不连线、不写 referenceResources。详见 [MCP 执行协议](mcp-execution.md)「色卡（强制，分镜前完成）」。

### 空间连续性合同

出视频前，每个场景先在内部定好空间合同，站位图就是它的可视版本：

- 区分真实空间和画面空间：门窗、家具、人物真实位置一旦由场景图、站位图或已认可的分镜确定，换机位时不移动它们；换机位只重新计算谁在画左、谁在画右、视线朝哪。
- 多人对手戏定好 180 度轴线，正反打保持在同一侧；确需越轴时，用人物移动、摄影机移动或新的关系镜头让观众看懂。
- 状态继承：每段视频的第一个镜头块重新写清场景、人物位置与朝向、关键道具状态；上一段的动作终点（文件落在桌中央、人已站到窗边）就是这一段的起点，不回滚。

### 提示词洁净与节奏

- 每段提示词脱离对话仍能独立成立：不写「上一段」「上一镜」「继续」「保持之前」「和前面一样」。
- 参考职责用自然语言绑定每张图的用途，例如「[@汤米] 锁定面部、发型与服装；【图1】站位锁定人物位置与朝向」；场景图里带人物时写明它同时是初始站位参考，纯环境图不虚构站位。
- 正文只写摄影机能拍到的客观事实：景别、机位与运动、画面里的左右前后、身体朝向与视线落点、手部受力、呼吸、口型、道具与环境的物理反应和同期声。不写文学比喻（如刀、霜、翻涌）、戏剧理论词或内部标签；不写本地路径、文件名、括号自注（如「（参考图3）」）和「End State」等元数据。
- 镜头块小标题统一写「起止秒｜景别｜机位与运动」。单镜通常 2–8 秒，一镜只承载一个核心动作和对应的台词；时长随台词字数和动作复杂度错落，非特殊需要不把整段切成等长。
- 同一角色连续说话超过约 6 秒，或出现关键态度转折时，切 1.5–3 秒的倾听者反应镜头，反应动作要有具体的身体变化，不写「看了一眼」「神情微变」。不连续 3 个镜头都用同一种单人近景。
- 长台词拆成 2–3 个气口，把视线、呼吸、手部动作嵌进台词进程里，不在一个引号里一口气念完。台词与剧本、音频逐字一致。
- 最后一个镜头块写清身体重心、双手落点和道具静止位置，作为下一段的起点。
- 默认不要背景音乐，只保留同期声、环境底噪和对白；用户明确要求时再加。

以上是默认写法；用户对风格、节奏或格式有明确要求时以用户为准。

## Frame 提示词

Frame 是 Video 的 `t=0` 首帧。提示词描述动作尚未发生或刚刚启动的预备状态，不描述动作已经完成的终态。

默认首帧已经被人物和剧情信息占用。只有镜头卡明确要求空镜、延迟揭示或纯环境转场时，才允许先出现无人画面。

推荐拼装顺序：

```text
[视觉风格]
+ [景别、机位、焦段与构图]
+ [精确主体引用与首帧体态]
+ [表情、视线与朝向]
+ [固定服装和必要状态变化]
+ [前景、中景、背景]
+ [关键道具]
+ [主光方向、色温、明暗关系]
+ [【色卡】[@色卡] 色调、明暗比例与关键 HEX]
+ [画质和一致性约束]
+ [必要负向约束]
```

示例结构：

```text
自然主义实拍，低饱和青灰色板，35mm 自然透视，平视竖屏中景，
[@林夏] 位于画面左侧三分线，右侧保留视线空间，三分之二侧身面朝右，
右手刚触到录音笔，手指微停，目光从录音笔移向画外的 [@周沉]，
[@周沉] 位于右后方虚焦区域，面朝左，保持克制站姿；
前景雨水沿站台玻璃滑落，中景两人隔着长椅对峙，背景列车灯形成纵深；
右后方冷白硬顶灯斜射，面部半明半暗，焦点落在林夏眼睛和录音笔，
前景玻璃、中景人物、背景列车灯形成三层纵深，服装与角色参考一致，
动作自然，细节清晰，无字幕，无水印，无画外文字。
```

### 内容忠实性

Frame 提示词是对 Shot 的视觉转换，不是第二次自由创作：

- 保留 Shot 中全部可见主体、空间层次、关键动作起点和道具；
- 保留指定景别、情绪、朝向和光线；
- 逐字复用适用的视觉规则、角色身份锚点和场景空间图；
- 保留 Shot 的机位、焦段、视觉焦点和连续性状态；
- 关键道具逐字复用尺寸、材质、方向、握持位置和当前损坏状态；
- 不添加 Shot 未提及的花瓣、烟雾、装饰、人物或物件；
- 风格词服务于内容，不能改变叙事情绪；
- 台词和音效不作为画面文字写进图片；
- 故事世界内真实存在的招牌或信件可以描述，字幕、水印和 UI 文字默认禁止。

### 首帧检查

正确首帧通常使用「刚触及」「即将抬起」「衣角初被风带动」等预备状态。

避免「已经拔剑」「跑到门外」「转身离去」等终态，也避免只写「正在奔跑」而没有可稳定成像的姿势。

## Video 提示词

默认走全能参考：视频垫的是资产（人物至少 3 个视角、道具、场景、站位图），不是镜头画面；正反打、对白覆盖和机位切换全部写在提示词里。多镜头片段按「[STYLE LOCK] → 参考职责 → 音轨 → 执行与连续性（轴线、屏幕方向、谁在左谁在右）→ 逐个镜头块（块间独立一行 `HARD CUT`）→ 结束状态」组织。参考职责里每个主体写成「[@主体名]：锁定什么、不继承什么」，站位图写成「【图N】站位：锁定人物位置、朝向与轴线，不决定景别」。

对话戏示例（正反打写在文字里）：

```text
执行与连续性：7 秒，3 个镜头，2 次硬切。[@汤米] 在画面右、[@亚瑟] 在画面左，保持 180 度轴线。
镜头一｜0—2秒｜双人中景：按【图1】站位，亚瑟把湿纸拍在桌上。
HARD CUT
镜头二｜2—5秒｜正打，越过汤米右肩拍亚瑟近景：亚瑟说出【音频1】。
HARD CUT
镜头三｜5—7秒｜反打，越过亚瑟左肩拍汤米近景：汤米只抬了一下眼，没有接话。
```

需要锁定构图或首尾状态时，才改走图片优先路线：Video 提示词从父 Frame 的首帧继续，重点描述时间变化。推荐结构：

```text
起始：复述与父 Frame 一致的起始姿态和空间关系。
动作：按时间顺序描述 1 到 3 个动作拍。
运镜：说明相机的叙事动机、方向、速度和落幅；没有动机时保持静止。
连续性：服装、外观、道具、光线和人物位置保持一致。
情绪：说明表情或节奏如何变化。
声音：必要的对白、口型或环境声提示。
结束：动作自然收住，给下一镜可衔接的状态。
时长：{秒数}。
```

示例结构：

```text
从首帧开始，[@林夏] 的右手拿起录音笔，先短暂停顿，再抬眼看向 [@周沉]；
[@周沉] 轻微收紧下颌，没有后退。镜头在 5 秒内从中景缓慢推近到林夏近景，
两人位置、服装、雨夜站台和冷白顶灯保持一致。林夏的神情从试探转为确认，
最后把录音笔停在胸前，动作自然收住。环境保持雨声与远处列车制动声，无字幕，无水印。
```

规则：

- 动作顺序与 Shot 一致，不增加新剧情。
- 每镜只保留一个视觉焦点、一个主要动作链和一个相机意图。
- 运镜只保留一次清楚意图，避免互相冲突的推、拉、摇、移同时发生。
- 单镜动作拍数量与时长匹配。
- 结尾保留可剪辑的稳定状态，并与下一镜的连续性进入状态一致。
- 提示词包含主体时，根据实时 schema 选择正确视频类型和主体 ID。
- 不把整段 Frame 画质词复制进 Video；只保留连续性所需信息。
- 表演按目标、策略和可见动作拍推进；用停顿、呼吸、视线、手部任务和对他人行为的反应表达状态，不直接要求「表演情绪」。
- 比例、分辨率、模型、生成模式和平台原生参考绑定属于节点配置时，不在提示词中重复。

## Audio 内容

对白 Audio：

- 文案从 Script 和 Shot 逐字复制；
- 使用角色主体绑定的真实音色 ID；
- 情绪、语速、语调和音量与 Shot 一致；
- 一条 Audio 对应一个明确说话者和一段连续台词。

音乐 Audio：

- `content` 写可执行的音乐提示词，包括情绪作用、进入与退出位置、乐器、速度、频率重心、动态和留白；
- `modelProvider` 使用实时 schema 支持的 `audio_music_mureka`、`audio_music_suno` 或 `audio_music_elevenlabs`；
- `mode` 使用 `song`、`instrumental`、`soundtrack` 或 `remix`，并遵守对应 Provider 的参考资源要求；
- 歌曲按需写入 `songName` 和 `lyrics`，纯音乐不伪造歌词；
- `generateCount` 只写实际需要的数量，不用多生成替代方向确认。

独立环境音或音效只有在实时 Provider 和模式明确支持时才创建并生成 Audio。否则把声音设计保留在 Shot 或 Video，并报告生成能力缺口；不要把环境音描述塞进 TTS 对白或音乐歌词。

普通 `createNode` 只能创建 Audio 的结构和 `content`。随后用实时 `updateNode.generationParams` 写入 TTS 或音乐所需配置；服务端生成计划仍会在报价前验证 Provider、模式、音色和参考资源。无法满足时报告能力缺口。

## 按 Scene 原子创建和制作

确认后的唯一 Script 先作为独立小批次写入并回读真实 ID。主体资产锁定后，先选择代表 Shot 所在的试拍 Scene，再按 Scene 调用 `createNode`。9 个 Scene 仍是 9 个 Scene 创建批次，另有一个小型 Script 写入；试拍阶段已经创建的 Scene 不重复创建：

1. 导演分镜与试拍确认后，只编译试拍 Scene 的完整镜头卡和最终提示词；试拍通过前，不编译其余 Scene 的最终提示词；
2. 每批包含一个 Scene 的完整子树，Scene 用 `parentIds` 指向已经存在的真实 Script ID；
3. Shot 用 `parentRefs` 指向所属 Scene；
4. Frame 用 `parentRefs` 指向所属 Shot，`content` 保存最终图片提示词；
5. Video 用 `parentRefs` 指向所属 Frame，`content` 保存最终视频提示词；其直接 Frame 父级必须收敛到唯一 Shot，并按该 Shot 内视频顺序提供 `nodeIndex`；
6. Audio 按叙事归属用 `parentRefs` 指向 Shot；新建 Audio 只保存结构和内容，不表示已经具备生成配置；
7. 每个新节点只提交实时 schema 正式暴露的字段；本批同时为每个 Shot 建一个组（`type=group`），把该镜的 Frame、Audio、Video 的 `parentNodeRef` 指向该组；
8. 每批使用最新 FULL 快照的 `projectId` 和独立幂等键 `film:<projectId>:graph:scene-<NN>:create:v1` 原子写入；`baseVersion` 仅作可选冲突检查；
9. 每批从 `structuredContent.output.createdNodes` 保存 `clientRef -> nodeId` 映射，再读取 FULL 快照验证当前 Scene 的完整关系；
10. 先完成已创建试拍 Scene 的剩余镜头，再处理尚未创建的 Scene；当前制作中的 Scene 通过生成与视觉验收后，才编译和创建下一个 Scene。全部 Scene 完成后再读取一次 FULL 快照，验证完整作品。

不要把同一 Scene 拆成逐层请求。同批新节点使用请求内引用；只有后续 Scene 连接调用前已存在的 Script 时才使用 `parentIds`。某批超时或返回不明确时，先回读判断该 Scene 是否已完整存在；保留已验证的前序 Scene，从第一个缺失或不完整的 Scene 恢复，不重放全片。

完整成片默认每个 Shot 至少一个 Frame 和一个 Video。只有用户明确要求「只要分镜图」或「不生成视频」时才停在 Frame。

## 生成前逐条校验

每个 Frame 和 Video 都检查：

- 提示词与对应 Shot 含义一致；
- 所有已建主体名称拼写准确；
- 主体 ID 来自最新列表；
- Frame 是首帧预备状态；
- Video 从该首帧自然发展；
- 本批 `parentRefs` 或已有 `parentIds` 指向正确；
- 本幕色卡主体已有图片，提示词含「【色卡】[@色卡]」行；
- 本镜的分镜图、补拍图、音频和视频已放进本镜组；
- 视频垫图齐全：出场人物各至少 3 个视角、场景图、对应状态的站位图、关键道具；没有垫正反打或补拍画面；张数不超过实时模型上限；
- 视频提示词写清轴线、屏幕方向和每个镜头块的正反打机位，块间有 `HARD CUT`；
- 时长足够承载动作和对白；
- 镜头卡已通过首帧占位、残留引用、空间、视线、物理、表演和复杂度审计；
- 节点 `content` 已经提交到画布；其他必需生成配置可由服务端解析，或具有实时 schema 正式字段的写入证据。

生成与状态查询按 [MCP 执行协议](mcp-execution.md) 及实时工具定义执行；每次新付费范围独立确认，回读真实媒体文件。
