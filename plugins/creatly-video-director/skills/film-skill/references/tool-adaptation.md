# 工具适配与画布执行

先发现当前可用工具并读取真实 schema。下表是职责，不是保证存在的 API。用户指定平台优先；能力缺失时继续授权内的文档、素材盘点与提示词准备，不伪造接口或回执。

| 工作 | 工具存在时 | 能力缺失时 |
|---|---|---|
| 规格/故事板 | 本地文档或平台故事板 | 本地可执行方案，平台 ID 留空 |
| 素材分析 | 查看实际图像/音视频和文本 | 标待分析，仅文件名不足以描述内容 |
| 创建/更新画布 | 使用当前插件/MCP真实工具，记录返回目标 | 本地节点清单与引用关系，不声称已同步 |
| 估价/生成/查询 | 当前模型列表、估价、提交、任务查询 | 标待执行，不以工具名称推定模型能力 |
| 资产绑定 | 按目标类型查询/绑定并读回 | 待绑定清单，保留真实输出 |
| 剪辑 | 当前平台或可用本地剪辑能力 | EDL/时间线及素材缺口，不声称已导出 |

## 真实 ID 与引用

区分本地 shot/clip 名称、平台 node/shot ID、task ID、供应商 resource_id、注册 asset_id 和当次引用标签。只用工具实际返回的 ID；本地标签不是平台 ID。资产引用应写清身份、构图、空间、道具、音色职责及不继承项。

若平台使用资产槽位，在引用音频之前查询目标；缺失时按当前合约补齐绑定并保留已有用途，再查询核对。平台采用请求内直接引用时，验证该请求实际传入的资源，不强制套用不存在的 key_element_audio 或 asset_bindings。

<<<image_N>>>、@资产等语法只在当前工具支持且已建立真实映射时使用。节点连线不等于请求带了该图片；提示词写了资产名也不证明约束已传入。

## Creatly / 元极调用

- 使用当前已安装插件实际公开的 MCP 和 schema。不要因为技能里的历史工具名而强行切换 /v2、旧 API、本地桥或其他渠道。宿主显示 unknown 或参数被拒绝时，按 [MCP 执行协议](mcp-execution.md#参数不可见与失败恢复) 核查；区分参数定义未显示、参数校验失败和业务前置条件不满足，不用试写批量节点猜字段。
- 读取当前画布，识别目标节点及状态，再更新允许修改的配置。生成中节点不改提示词或生成参数；先查询原任务，避免误触编辑锁或覆盖结果。
- 显式设置已核验模型、画幅、分辨率、数量，先让节点与实际提交参数一致，再估价。生成前在对话里记录本批授权；已批准的不再引导用户点击画布确认。
- 当前 generateNodes 等工具若提供预算上限或幂等键，按真实 schema 使用。超时先用原标识查询，不换新键重复提交；新增付费重试重新核对授权和预算。
- 对已有项目接着做，不因调用技能另建重复项目。独立新片按用户要求建立新项目，不覆盖参考作品。

## 文本节点直接输入

创建剧本、对白或笔记时仍使用 type=text，content 表示直接显示的正文，不是要求模型执行的提示词。修复后的 MCP 在内部写入节点 generatedContent，使画布无需生成即可预览。创建后读回正文；无需为显示文字调用 generateNodes。调用旧部署时若正文只落在 generationParams.prompt，记录服务版本不匹配，不以文本生成代替直接写入。

## 生成与自动挂载分别验收

正常生成工具应由服务端把结果挂到目标节点。代理负责提交、查询和检查，不默认在图片完成后再手动回写一次。

结果处理顺序：任务终态与输出 → 目标节点最新媒体/状态 → 实际可查看内容。若任务成功但节点没有新媒体，保留 task ID、node ID、输出及错误；查询确认是否仍同步中、节点版本冲突或服务错误。只有真实接口明确要求绑定、且属于已授权制作操作时才补做绑定。没有该条件不修改版本号、解锁生成中节点或反复更新输出。

已生成不等于已挂载；已挂载不等于视觉通过。挂载异常不能通过付费重生成修复。遇到需要服务端排查的故障，交付证据和原图路径，其他无依赖工作继续。

## 持久化与交接

保存真实提交文本、参数、素材顺序、请求/任务标识、输出与采用状态。新稿另存版本；旧输出仍关联旧输入。工具未提供底层模型身份时只记录工具和平台显示名。无需在技能或文档存储密钥、令牌、登录态。
