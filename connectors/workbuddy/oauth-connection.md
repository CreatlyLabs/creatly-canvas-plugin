# WorkBuddy 官方连接器授权与续期

在 WorkBuddy 的 Creatly 连接器页面点击“连接”。WorkBuddy 云端根据 MCP 元数据动态注册客户端、发起浏览器授权，并管理令牌保存、续期和请求注入。用户在 Creatly 网站登录并确认账号、空间和权限；连接是否完成，以 WorkBuddy 的连接状态及一次只读查询结果为准。

## 连接与权限

- 官方包声明 `auth_mode: "server-side"`，`server_auth.auth_type` 为 `mcp_oauth`。资源地址与 mcp.json 的 HTTPS 地址一致，不包含 client_id、client_secret、redirect_uri 或真实令牌；这些注册结果由平台管理。
- `mcp.json` 的唯一 Server 键名与 connector source 一致。只使用当前连接器提供的工具，不创建第二个手动 MCP 连接。
- `mcp:read` 用于读取项目、画布和结果；`mcp:write` 用于修改节点、上传素材和管理主体；`mcp:generate` 用于提交生成任务。获得生成权限不代表用户批准任何新增支出，付费任务仍按实际报价和用户授权执行。
- 官方市场的云端回调由 WorkBuddy 生成，不能在技能中编造或替换成 workbuddy:// 或本机 HTTP 地址。旧客户端使用原生协议或本机回调时，以宿主实际注册的地址为准，不把旧客户端流程套用于云端连接。

## 会话里开始授权

用户要求“开始授权”时，先核对连接状态。已有连接可用就做一次只读验证；正在连接或等待用户确认时继续使用原流程。需要新授权时只发起一次连接；宿主已打开网页后，不再让浏览器或其他打开工具访问同一授权链接。原请求已取消、过期或失败且用户要求重试时，才开始下一次。

## 持续使用与排障

WorkBuddy 云端保存和续期凭据，不让用户手动填长期 Token，不读取本机凭据文件。重新打开任务或更新同一环境连接器时先复用已有连接；凭据有效期以服务端签发结果为准。切换环境、撤销授权或刷新凭据到期后，按平台提示重新连接。

- `invalid_redirect_uri`：核对平台注册的 HTTPS 回调与后端部署；不能通过手改授权链接或降低回调校验解决。
- `invalid_client`：检查客户端注册是否存在及认证方法，反复登录不能恢复被删除的注册。
- `invalid_grant`：检查授权码或刷新凭据是否过期、已用或已撤销，不循环重投同一请求。
- `401`：由 WorkBuddy 走正常续期流程，确需重新连接时只发起一次。
- `403`：检查账号、空间和授权范围，不自动重复登录。
- 连接超时：先核对平台最终状态，未得到完成回执不能声称授权成功。

排障仅记录客户端版本、连接器版本、环境、时间、状态码及 traceId。不要在聊天、技能或上传文件中记录 Cookie、授权码、state、签名 URL、client secret 或令牌。
