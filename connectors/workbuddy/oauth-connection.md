# WorkBuddy 账号连接与续期

在 WorkBuddy 的 Creatly 连接器页面点击“连接”，由 WorkBuddy 发起并管理 OAuth。浏览器打开当前环境的 Creatly 登录与授权页，用户确认账号、空间和权限后，回调将授权结果交回 WorkBuddy。网页显示“已确认授权”不等于连接已完成，应以 WorkBuddy 的连接状态及一次只读项目查询结果为准。

## 回调与连接标识

- `mcp.json` 的唯一 MCP Server 名称与 `connector-meta.json` 的 `source` 一致；技能使用这个已安装连接器提供的工具，不再创建第二个手动连接。
- 正式连接器的原生回调为 `workbuddy://workbuddy/mcp/connector:creatly-canvas/oauth/callback`；平台也可能提交冒号编码为 `%3A` 的形式。测试与开发包使用对应的 `-test`、`-dev` 标识。
- 后端按精确地址登记和校验回调，继续要求 PKCE S256。其他协议、主机、路径或附加查询参数不因名称相似而放行。
- 部分客户端版本可能使用本机 HTTP 回调，以宿主实际登记并发起的地址为准；不要自行替换回调或重复打开授权链接。

## 会话里开始授权

用户要求“开始授权”时，先核对宿主连接状态。已有连接可用就做一次只读验证；正在连接或等待用户确认时继续使用原流程。需要新授权时只发起一次宿主连接；宿主已打开网页后，不再让浏览器或其他打开工具访问同一授权链接。原请求已取消、过期或失败且用户要求重试时，才开始下一次。

## 持续使用与排障

宿主管理令牌保存和自动续期。重新打开任务或更新同一环境的连接器时先复用已有连接；访问令牌和刷新令牌的实际有效期以服务端签发结果为准。切换环境、撤销授权或凭据过期后按宿主提示重新连接。

- `invalid_redirect_uri`：核对连接器 source、精确回调及后端部署，不更换成任意回调地址。
- `invalid_client`：检查客户端注册或认证方式；反复登录不能补回被删除的注册。
- `invalid_grant`：检查授权码或刷新凭据是否过期、已使用或已撤销，不循环重投同一请求。
- `401`：交给宿主正常续期，确需重新连接时只发起一次。
- `403`：检查账号、空间和授权范围，不自动重复登录。
- 连接超时：先核对宿主最终状态；未得到完成回执不能声称授权成功。

排障仅记录客户端版本、连接器版本、环境、时间、状态码及 traceId。不要在聊天、技能或上传文件中记录 Cookie、授权码、state、签名 URL、client secret 或令牌。
